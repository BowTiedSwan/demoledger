## Additional deployment checks (OWASP_ANALYSIS §"Additional deployment checks")

These are production prerequisites. None is a vulnerability in the local demo.

1. **SPA framing protection.** Serve `frame-ancestors 'none'` and `X-Frame-Options: DENY` as HTTP headers for the SPA HTML. A meta CSP cannot enforce `frame-ancestors`.
2. **HTTPS and secrets.**
   - Enforce HTTPS, so `Secure` cookies and the trusted origins are HTTPS.
   - Use TLS to the database.
   - Verify at deploy time that `current_user` is `ledger_reader` / `ledger_app` and never the owner.
   - **F-30 (T-270, fixed; verification pending):** a boot-time assertion (`apps/api/src/lib/role-check.ts`) makes the API refuse to start unless both pools run as `ledger_reader` / `ledger_app` with `rolsuper` and `rolbypassrls` false. A superuser bypasses even `FORCE` RLS, so this turns deployment check #2 into an enforced check.
3. **Public demo accounts.** The quick-fill credentials are for fictional, expendable data only. Remove them, or gate access to them, before any shared deployment; they also expose the shared AI quota.
4. **Auth endpoint surface.** Allow-list the Better Auth endpoints the UI uses (sign-in, sign-out, get-session) and block the rest, as `/api/auth/organization/*` already is.
5. **Residual client state.** Add cross-tab sign-out and server-side revocation to session-lifecycle QA.
6. **Audit and conversation privacy.** Document retention, backups and operator access for `ai_requests`, `ai_tool_calls`, `ai_conversations` and `ai_messages` before using real data (see also OWASP-04).
